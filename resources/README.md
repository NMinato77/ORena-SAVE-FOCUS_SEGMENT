# `resources/` — offline model assets

Everything in this folder is **copied into the container image** at build time and
is available at inference. `prepare_assets.sh` materializes the model snapshot
from an external cache before `do_build.sh`. Large model assets are intentionally
not committed to this public source repository; they must be supplied locally
when building the offline image.

| File | What it is | Replace it? |
|:--|:--|:--|
| `qwen3-vl-8b/` | Qwen3-VL-8B-Instruct local snapshot | generated by `prepare_assets.sh` |
| `q1_tfidf_r5_router.joblib` | Frozen question-only Q1-R5 capability router | keep with its recorded SHA256 |
| `q2_siglip_base_patch16_384/` | Frozen CPU text-only SigLIP encoder for H2 | generated by `prepare_assets.sh` |
| `q2_siglip_text_r5.joblib` | Frozen Q2 SigLIP-text classifier | keep with its recorded SHA256 |
| `q2_siglip_manifest.json` | Q2 asset and classifier hash manifest | no |
| `specialists/general_final_union_adapted_weights.safetensors` | Stage A-bound final General LMV state pack | copied from validated final checkpoint |
| `specialists/agg_final_union_adapted_weights.safetensors` | Stage A-bound final Aggregation LMV state pack | copied from validated final checkpoint |
| `format_reducer.py` | question-only format contract and reducer | no |
| `routing.py` / `multiple_choice.py` | question-only format helpers | no |

`q1_tfidf_r5_router.joblib` is loaded once at startup by `q1_router.py`. Its
question-only prediction is retained as the first fallback route:
Aggregation → AGG/R0, Temporal → General/R0, and
Object/Event/Complex → General/R1. If startup loading fails, the explicit
startup chain continues to the question-only Q0 rule router.

The packaged H2 candidate loads the local CPU-only SigLIP text encoder and Q2
classifier once at startup. H2 applies Q2 Aggregation precedence, then the Q0
or Q1 Temporal rescue rule. If the H2 package gate fails at startup, the
submission retains the tested Q1-R5 route for that run; no partial specialist
or sampling route is activated.

Final General and Aggregation LMV specialist packs were artifact/config-bound by
Stage A, and runtime forward binding was implemented and verified in Stage B.
The production runtime keeps one frozen base with two ordinary tensor banks;
each specialist switch copies the complete 560-tensor state, synchronizes the
device, and only then updates the active identity. Missing or invalid specialist
assets and activation failures remain hard failures; no historical weight is
used as an implicit fallback.

## Things to get right

**There is no internet at inference time.** The container runs with networking
disabled. `inference.py` uses `local_files_only=True` and loads the model from
`resources/qwen3-vl-8b`, so no model hub, tokenizer, checkpoint, or font download
can occur at runtime.

**Load your model once.** One container run answers a whole batch of questions, so
the checkpoint is loaded once and reused across every question in that batch. Keep
model loading outside the per-question loop in `inference.py` — that is where the
setup allowance in the latency budget comes from.

The Qwen base model is about 17.5 GB and is below the template's 50 GB per-layer
limit. It is copied as the required four safetensors shards. Final specialist
packs are validated separately before model loading.

**Big weights make big images.** The whole image is pulled before your code starts.
That pull is infrastructure overhead and is not charged against your latency
budget, but it does slow every submission cycle, so keep the image only as large as
it needs to be.

`prepare_assets.sh` supports both execution contexts. Inside the DevContainer it
uses the standard `/cache` mount; on the host it automatically resolves the sibling
`../cache` directory and the repository's `outputs/` directory. Set
`QWEN_MODEL_PATH`, `Q2_ENCODER_PATH`, and/or `Q2_ROUTER_PATH` explicitly when
the host storage layout differs.
